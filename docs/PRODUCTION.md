# Production handoff — Touchline Studio V2

## Prepare a segment

Load the intended match and check the XI/source labels, match date and supplied statistics. Rename the analysis, import the still or short clip and prepare the explanation. For reconstructed play, complete calibration, player/team assignment, uncertainty review and corrections before building the replay. Keep the original footage and export a portable project pack before the show.

Use consistent team colours, a short programme caption and a small number of readable graphics. Review source cutouts before enabling them; virtual players are the clean default. The source comparison explains where the reconstruction comes from. See [the V2 operator guide](STUDIO_V2.md) for the full workflow and limits.

## Screen and output setup

Use a current Chromium browser over HTTPS on a desktop or landscape touchscreen. Presenter mode gives the analysis most of the screen and temporarily enables Live follow. Programme opens a separate clean window. Keep both windows on the same origin and browser profile. Move the output to a second screen or capture its window in OBS. An independent OBS browser engine has separate storage and cannot receive this browser's production channel.

Preview edits are held until Take to programme unless Live follow is enabled. Source transport is shared for the currently taken project. Use Blackout to cut the programme to black; take the preview again to restore it. Source audio is muted on programme; exports are silent for studio commentary. Change the caption under Display.

Stills export as 3840 × 2160 PNG. Films render frame timestamps at 1920 × 1080 / 25 fps using WebCodecs and Mediabunny, with H.264 MP4 if supported and WebM otherwise. Source exports cover up to 20 seconds; tactical storyboards up to 60 seconds. Export the film and inspect it before transmission. This browser tool does not supply native SDI, NDI, EVS integration or certified broadcast timing.

## Storage and recovery

- Projects save to IndexedDB; the local active-document cache supports restoration of older projects. The library retains up to 100 entries. Browser storage is not a server backup.
- Portable `.touchline.zip` packs include referenced source media, tracking, graphics, notes and document data, up to 200 MB of source files. Importing creates separate document/media IDs. Use this to transfer between devices, browser profiles and site origins.
- `.touchline.json` contains the editable document only. Source blobs are separate. Keep originals if using this format.
- The installed app caches its shell/catalogue and vision assets after use. Uncached media engines and live data routes still need a connection. The programme can use a prepared local segment when the data provider is unavailable.
- Data refresh is explicit through `npm run data:refresh`; review coverage and manager identity sources before committing/deploying a refreshed snapshot.
- No paid service, database subscription, cloud footage upload or secret has been provisioned.

## Release verification

The automated suite covers competition/squad/manager integrity, formations, storyboard interpolation, document validation, the football API, homography/inverse projection, field-attached graphics, robust camera compensation, translated player-patch tracking and conservative uncertainty handling. TypeScript and the Vite production build pass.

Browser verification uses a synthetic ten-second, 25 fps clip with known player motion, generated by `scripts/make-test-clip.py`. The completed workflow produces 41 tracking samples for six marked players, supports analyst review and builds editable scenes. The supplied reference still is used only locally to verify actual person detection; imported match images are not committed or deployed. The cloud browser lacks WebGL, so visual QA exercises the Canvas 3D fallback and TensorFlow CPU/WASM detection path. Rehearse the WebGL renderer, studio touchscreen and capture chain on the actual production machine before a live show.
