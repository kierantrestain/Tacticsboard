# Studio 6 operator handoff

Use Studio **6.0.1**, control protocol **4**, from one matching Studio Hub package. The source commit and build date are recorded in the package's BUILD-INFO.json. Review the production evidence for the tested environment and outstanding studio checks; these instructions are not certification for recording.

1. **Start.** Install Node.js 22 or newer. Unzip the Hub, open its folder and run `node scripts/studio-hub.mjs` (or Start-Studio.command / Start-Studio.cmd). Keep the terminal and show computer awake. Open the printed producer URL; normally http://localhost:4174. The app's resources, models, reports and historical event archive are included; online source refresh needs internet.
2. **Open the correct episode.** Use the command centre → Open episodes & recovery, or click the Touchline brand. Create/name, resume or duplicate the whole episode. A named episode remains named when changing matches. A duplicate has independent editable episode state. Check the rundown and all media references. Browser/address/profile storage is separate; a saved browser project is not an external backup.
3. **Transfer completely.** In Import select the `.touchline.episode.json` manifest and **every** numbered `.touchline.partNNNN.zip` together. Missing/corrupt volumes are rejected before publishing staged sources/resources. Small legacy `.touchline.zip` and JSON remain compatible; JSON does not carry media. A large source is preserved byte-for-byte through bounded volumes, so original trims, tracking and timestamps need no segment-offset approximation.
4. **Prepare privately.** Recall a moment or import/open a source. Playback resumes paused, with follow off. Make the picture adjustment, timed graphics, reviewed player observation/reconstruction or source-versus-3D explanation. Save a new moment or update the selected one. Import/process/export/private recall must preserve the held programme.
5. **Prepare data.** Data centre → Maps & radars. Load the explicitly historical 2017/18 club archive or a permitted event import. Check coverage. Configure maps/profiles/radars or 2–5 player/team comparisons. Save their source/cohort snapshot to the rundown. Current-season PL located events require a permitted provider export/feed; ESPN/FPL totals are not a substitute.
6. **Keep source updates deliberate.** In TV design → Match source & score corrections, refresh the prepared match explicitly. Background reports update research only. Manual score/state overrides need a reason, survive source refresh and can be removed to restore the latest prepared source. Update moment deliberately to revise a saved shot. Player-editor substitutions remain labelled analyst selections; re-open the source match's confirmed XI deliberately rather than silently replacing a prepared lineup.
7. **Arrange the show.** Search/order/group the rundown, set durations and shared script, and add distinct Host 1 / Host 2 / Producer notes. Each host may privately inspect notes without changing preview; only the owner recalls shared scenes. Check every shot, including source availability and uncertainty/review state. No automatic tracking identifies unseen players or establishes exact ball movement.
8. **Pair hosts.** Connect tablets → Create filming session. Both tablets use the displayed trusted LAN address; each receives its own expiring one-use code. Check v6.0.1 on the tablets. Enable host controls, then request/pass ownership explicitly. Enabling controls does not enable TV follow. Use the map/radar filters and event-inspection controls on prepared data graphics. Source/team/scene/episode/control-owner fences reject stale commands.
9. **Present.** Open the clean programme on the show computer, then inspect its actual downstream display/capture. Opening output does not take. Take to TV explicitly; enable Live follow only for deliberate shared edits. Hold pauses/stops following. Blackout/Restore retain exactly the held shot. The clean frame is 16:9; presenter/research controls and private notes stay off the output.
10. **Reset and recover by scope.** Clear drawings affects the current drawing layer; Undo restores it. Restore saved moment reloads only that moment. Reset draft tactics creates a recovery checkpoint and affects the current setup, not other saved moments. Fresh episode checkpoints the existing episode. Save recovery checkpoint before substantial preparation. Episodes show pending/saved/failed; a failed write retains the previous valid state. Recovery reopens paused/private and requires pairing/control ownership to be re-established.
11. **Back up and export.** Use command centre → Back up complete episode, or Export → Portable project. The backup preflights referenced media and snapshots. Prepare/download the manifest and every ZIP, or save all files to a chosen folder when that browser supports it. Keep one valid complete set. After rendering a still/film, use the visible **Download file** link in the export-ready message. 4K PNG and silent 1080p/25fps films export the current graphic/view; preview the actual downloaded film. Data tables export all selected metrics/events, not just the visible metric group. Inspect transferred/imported media before filming.

On a tablet sleep/reconnect, unsent gestures are discarded; verify the current scene and owner before continuing. Producer loss/refresh or episode change disarms host control and stops follow. Hub restart invalidates temporary sessions: restart the Hub, reopen the producer, pair both roles again, then enable deliberately. Browser receipt is not proof that a TV/OBS/capture device has received the correct frame.

The final on-site rehearsal must cover physical touch/Wi-Fi, representative licensed long/VFR footage, native decoder/GPU paths, complete file downloads/transfers and the actual display/capture chain. Use the evidence matrix to distinguish checks actually completed in emulation from those still outstanding.
