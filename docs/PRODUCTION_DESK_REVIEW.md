# Production desk review — 3.1

This revision addresses workflow reliability as well as presentation. The standard is a predictable operator desk: prepare privately, see the held programme, know which source and caption belong to each shot, and recover without accidentally taking a different view.

## Element-by-element findings

| Element               | Fault found                                                                                                                                   | Result in this revision                                                                                                                                                                     |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace hierarchy   | Too many equally prominent controls, small icon-only inspector navigation, full-size cards hiding the rest of the rundown                     | Larger preview, neutral navy/graphite chrome, cyan preview and red programme tally, persistent output monitor, labelled panel selector, six primary drawing tools and an extended tool menu |
| Programme opening     | Opening or reconnecting output implicitly took the current editor                                                                             | Opening output only opens the receiver. The existing held snapshot is returned unchanged                                                                                                    |
| Blackout / restore    | Both operations rebuilt a snapshot from the current preview                                                                                   | Blackout covers the held snapshot and disables live follow. Restore returns that same board, phase, data and caption                                                                        |
| Presenter mode        | Entering presenter mode enabled live follow and took the editor, including during blackout                                                    | Fullscreen is independent of output. Presenter controls explicitly take, follow, hold and black/restore                                                                                     |
| Output status         | A generic heartbeat could imply the wrong take was being shown                                                                                | The receiver acknowledges the take ID and blackout state, and returns a sampled rendered frame. “Awaiting output” is distinct from “Output received”                                        |
| Playback isolation    | Transport identified only the project; held phase time was not in recovery snapshots                                                          | Transport identifies the exact take, rejects stale messages and cannot update blackout. Phase time travels with the snapshot                                                                |
| Export                | Offline rendering changed the same playhead used by live follow                                                                               | Film rendering holds follow and restores preview position afterward. Emergency B blackout remains available                                                                                 |
| Saved shots           | Captions and report values remained dependent on mutable shared state                                                                         | Each new shot saves branding/visibility, report values, selected metrics, reviewed source tracking and a view thumbnail                                                                     |
| Editing a saved shot  | Only saving another shot or duplicating was available                                                                                         | Update shot preserves ID, order, title, planned duration and presenter script, and clears its review status. Unsaved preview changes are visible                                            |
| Caption review        | The desk canvas did not show the caption that would go to output                                                                              | The preview footer shows the caption; the selected shot exposes it beside presenter notes                                                                                                   |
| Rundown               | Large expanded cards, timers reset when changing panels, broken source shots could not be inspected                                           | Compact rows expand for the selected shot; clock state survives panel switches; missing-source shots can be inspected or removed while take remains blocked                                 |
| Pre-show preparation  | No consolidated readiness view                                                                                                                | Show panel links match/source/tactical preparation and reports readiness for every saved shot                                                                                               |
| Source readiness      | Metadata alone could allow missing source files to be taken                                                                                   | Local source bytes are checked; missing files and invalid ranges block take. Footage with no selected source has an import action and no misleading board-playback controls                 |
| Source ranges         | Selecting a source discarded its prior in/out points                                                                                          | Each source retains its range, including portable-pack remapping                                                                                                                            |
| Data cards            | Fixed long metric lists, inherited statistics from another fixture                                                                            | Up to eight selectable supplied metrics, frozen saved reports, explicit refresh and a fixture/report identity guard. Empty selections cannot be taken                                       |
| Match switching       | Late report responses could overwrite a later selection; a same-match player card could replace tactical work                                 | Latest selection wins. Switching fixtures resets report/player/caption context. Opening a card for the current fixture preserves its storyboard                                             |
| Reconstruction        | Building replaced the whole storyboard and the tracking source could keep overriding subsequent edits                                         | Reviewed observations append as editable phases. The board detaches from source-driven replay while original media/tracking remain available                                                |
| Calibration review    | Later calibration/target edits could leave a review flag valid                                                                                | Changing a source's landmarks or targets invalidates that source's tracking review. Invalid or unreviewed tracking blocks output                                                            |
| Repeated recall       | A deleted/replaced saved phase could be recreated with a different ID on every recall                                                         | Restored phases retain the saved scene ID; repeated recall does not create duplicate phases                                                                                                 |
| Recovery and feedback | An old “checked” time lacked a date; “saved” could be shown before persistence completed; partial media imports could disappear from the list | Data freshness includes date and UTC time; saving has a pending state; successfully imported files remain listed after a later import fails                                                 |

## Acceptance evidence

- 75 automated tests in 11 suites pass. Added controller/model cases cover reopening, exact blackout restore, stale transport, export isolation, missing source bytes, frozen captions/reports/tracking, metric validation, stable shot update identity, fixture races, same-match storyboard preservation, source trims, calibration invalidation and appended reconstruction. Existing API, season, player history, geometry/tracking, cache and portable-pack checks remain in the suite.
- TypeScript and the Vite production build pass. The media and 3D engines remain split into separate bundles; Vite still reports their large chunk sizes.
- Desktop browser checks exercised a deliberate take; a different caption prepared while black; exact restore; live caption following; hold followed by a private edit; entering/exiting presenter mode during blackout; compact shot recall/update/review; four selected player-card metrics; saved report recovery; the pre-show summary; and a blocked take from a footage view without media. The held programme remained visible while the missing-source preview was open.
- The programme receiver displayed the selected match/player card with its saved caption. Its returned thumbnail appeared on the desk. The save indicator reached “Saved on device”.
- Portable-pack tests preserve source bytes, remapped ranges, cues and saved reports. This revision does not claim a newly completed browser ZIP handoff or codec/hardware matrix.
- Browser QA uses the managed static production build. Live public-feed validation from the prior revision remains recorded in `PRODUCTION.md`; this static preview has no API backend. Deployment-specific full-prebuild results are recorded on the release PR.

## Remaining requirements before relying on it for a live show

| Requirement                    | Current boundary                                                                                                                                                   | What establishes readiness                                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Complete commercial match data | Public reports expose supplied fields and have variable coverage. Full optical tracking, every event metric and guaranteed historical availability are not present | Select and integrate a licensed provider with agreed competitions, seasons, metrics, refresh behaviour and service terms                     |
| Video position fidelity        | Reconstruction is analyst assisted. Camera cuts, occlusion, perspective and identity errors require review; unseen players cannot be recovered                     | Rehearse representative show footage and evaluate against trusted tracking before treating positions as measured truth                       |
| Studio output chain            | Same-browser clean window and receiver acknowledgement are implemented; native SDI/NDI/EVS and downstream on-air confirmation are not                              | Validate the actual touchscreen, graphics machine, OBS/vision mixer, frame rate, display scaling, capture colour and failover procedure      |
| Cross-device production        | Local projects, one browser profile and portable handoff; no shared producer/presenter session                                                                     | Add authenticated session transport, conflict handling, media synchronisation and operational monitoring if the show needs multiple machines |
| Camera persistence             | Named 3D camera presets are saved. Arbitrary orbit/zoom is not a saved custom camera pose                                                                          | Add explicit camera-keyframe storage if custom 3D angles must be recalled exactly                                                            |
| Operational recovery           | Device autosave and export packs, with honest missing-source checks                                                                                                | Keep an exported show pack and rehearse reload/reopen and fallback on the actual production machine                                          |

“Output received” means the browser receiver acknowledged the take. It does not mean the programme is on air in a downstream broadcast system. These boundaries are surfaced in the Show checks and operator documentation rather than hidden behind a generic ready indicator.
